Spellcheck that read the thread.

Readback underlines the slips your spellchecker can't see: her name spelled wrong, her amount with two digits swapped, a Thursday that's really a Tuesday. Every squiggle shows the line in her email it was checked against. It runs in your browser and sends nothing.

Try it in your browser, no install Install from source Firefox build

Made for Gmail on the web. On any other site, select the message and choose “Use as Readback context”. Free and open source.

Sample thread transcript.

  1. Kathryn writes: can you confirm the $1,250 deposit, drop off the keys on Thursday the 12th, and send the signed lease back? She signs Kathryn.
  2. Sam starts a reply, “Hi Catherine,”. Readback underlines Catherine.
  3. The card says Signs as Kathryn and cites her signature. One click changes the name to Kathryn.
  4. Sam types “The $1,520 deposit is confirmed”. Readback underlines $1,520 and says the thread has $1,250, digits swapped. One click fixes it.
  5. Sam finishes the reply. The pill reads All covered.

It sits in the reply box and stays quiet.

Most replies get nothing from Readback: no banner, no score, no rewrite. When a name, number or date in your draft nearly matches one in her message, it underlines it. Hover to see why, click to fix. Ctrl+Z undoes it like any other edit.

Names, checked against her signature.

Readback reads the names in her signature and your To field, and catches the near-misses: Catherine for Kathryn, John for Jon, Stephen for Steven.

Never fires. Write to Bob when the thread says Kathryn, and nothing happens. A different person isn't a typo.

Amounts and order numbers, digit by digit.

Swapped digits against the amounts and IDs in her message are flagged. Order numbers are flagged for a single wrong digit too.

Never fires. Counter-offer $1,200 and Readback stays quiet. It flags transpositions, not negotiations.

Dates that don't match the calendar, or her message.

A weekday and date that disagree, or a near-miss of the day she proposed. And a small pill counts what she asked that you haven't answered yet, so you don't need to reread.

Never fires. Propose a different day entirely and Readback assumes you meant it.

How it works, without a server.

The thread is the dictionary. Readback compares your draft only with the message you're answering, never with English in general.

In her message The rule In your draft Result
Kathryn A near-miss of a name she uses: one letter off, or a known variant Catherine Squiggle, with the signature as the citation
$1,250 The same digits in a different order $1,520 Squiggle, with her line as the citation
Thursday the 12th A different day altogether is a new proposal, not a slip Monday the 23rd Nothing

  • Why not flag every unknown word

    A grammar-style checker flags every word it doesn't know. On real replies that is a wall of red. Readback only flags near-misses of something in the thread.

    0 of 48 deliberate look-alike cases flagged in our test corpus. The corpus was written by the engine's author in one sitting, so treat it as a regression net, not a benchmark.

  • The mail page is never edited

    Squiggles are drawn with the browser's CSS Custom Highlight API, so the page's own text and layout are untouched. Fixes go through the editor's normal undo.

    4 to 9 ms engine time at the 95th percentile for a 2,000-word thread plus a 500-word draft. The budget is 16 ms. Three batches in the last run: 4.2, 8.5 and 9.0 ms on a busy laptop, gated in the test suite.

  • It goes quiet instead of guessing

    If Gmail changes its layout, Readback stays silent and the select-as-context path still works anywhere. The optional on-device model only adds “looks answered”. Every guard works without it.

    TypeScript WXT for Chrome and Firefox, chrono-node for dates, MIT licensed. No server to run.

There is no server to send it to.

Open DevTools, go to the Network tab, and write a reply in Gmail. Readback adds zero requests. The only host permission is the mail site itself.

From wxt.config.ts. No remote origin appears in the policy, and a lint rule fails the build on fetch, XMLHttpRequest, WebSocket and sendBeacon.

Where it reads
Gmail on the web. Any other text box through “Use as Readback context”.

Build it

git clone <repository-url> readback
cd readback
pnpm install
pnpm build

Needs Node 24 and pnpm. The repository link goes here once the project is published.

Chrome and Edge

  1. Open chrome://extensions and turn on Developer mode.
  2. Choose Load unpacked and pick .output/chrome-mv3.
  3. Open a reply in Gmail and type a name that nearly matches the sender's.

Firefox

pnpm build:firefox
  1. Open about:debugging#/runtime/this-firefox.
  2. Choose Load Temporary Add-on and pick .output/firefox-mv3/manifest.json.

Open source, MIT licensed.

The engine is plain TypeScript with one dependency, chrono-node. There is no server, account or telemetry to remove, so reading the code takes an afternoon. The web app on this site imports the same engine as the extension.

Where help is wanted

  • Real Gmail snapshots. The adapter was built against synthetic fixtures. Sanitised captures of today's reply box would let us retune its selectors.
  • A run in Firefox 140 or later. Whether wavy underlines render in Firefox's highlight API is unknown.
  • False positives. Short names like Tim and Tom are the known risk. A report with the thread and the draft is the most useful issue you can file.
